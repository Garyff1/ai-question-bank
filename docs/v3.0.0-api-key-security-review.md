# v3.0.0 RC003 API Key 安全审查

## 结论

RC003 已完成客户端 API Key 的基础防泄露强化，适合由开发者使用独立低额度 Key 进行内部测试。它不等同于第三方渗透测试或正式商业安全审计。

## 已完成措施

- 敏感值继续通过安全存储保存，新增安全存储读取与迁移自检入口。
- API Key 输入框默认隐藏，只允许短时间查看；应用进入后台、锁屏或离开配置页时立即隐藏。
- API 配置页通过 Android `FLAG_SECURE` 禁止系统截图和最近任务缩略图采集。
- Android Manifest 禁止应用备份，降低 Key 被普通备份导出的风险。
- 不提供“复制完整 API Key”按钮。
- 新增统一日志与错误脱敏，对 Bearer、常见 Key 参数和 `sk-` 风格 Token 进行替换。
- API 连接失败只保留可操作的状态信息，不回显请求头或完整底层异常。
- Release 界面不展示安全存储内部调试信息；自检入口仅在 Debug 构建显示。

## 自动化验证

- Key 遮挡不会显示完整值。
- Bearer、命名参数及常见 Token 格式可被脱敏。
- 应用离开前台时临时可见状态立即关闭。
- 旧明文配置仅在安全写入、回读成功后清理；失败时保留旧配置以防数据丢失。
- 官方账号登出不会误删用户自己的 API Key。

## 静态扫描结果

对源码和文档进行了疑似密钥模式扫描。命中仅来自测试用假值、`.env.example` 占位符、环境变量读取代码和后端测试夹具；未发现应提交的真实凭据。APK、构建目录和本地虚拟环境不纳入源码提交。

## 仍需真机确认

1. 不同 Android 厂商对 `FLAG_SECURE`、最近任务缩略图和分屏的实际行为。
2. Keystore 在覆盖安装、系统升级、锁屏方式变化后的持久化行为。
3. 2—3 台手机上的剪贴板、输入法联想和无障碍服务风险提示。
4. 崩溃收集平台启用后是否保持脱敏。
