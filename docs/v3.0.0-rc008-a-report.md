## F01：批次检查点与部分结果恢复

### 修复内容

- `AiJsonBatchCollector` 在每批接受有效对象后发布检查点，并等待异步持久化完成。
- 后续网络请求超时、429、服务商错误或连接异常时，如果已有有效对象，则返回当前检查点，不再丢弃前面批次。
- 首批即失败时仍保留原始错误，不伪造部分成功。
- 用户取消时停止后续请求；取消异常抛出前会等待最新检查点写入。
- 试卷页面收到检查点后同时更新本地试卷列表和未完成编辑草稿，重启后仍可找到已完成内容。
- 继续补题同样按批次覆盖保存，只补当前缺失题型，并继续受 API Cost Guard 请求上限约束。
- 单个模型对象在转换时异常，只剔除该对象，不再让整份已收集试卷失败。

### 用户可见变化

- 部分成功弹窗会显示已保存题数、缺失题型、结构无效数、偏离资料数、重复数和超配额数。
- 因接口异常中断时明确提示“此前成功题目已保留”。
- 用户取消后，如果已有检查点，会提示实际保存的有效题数。

## F02：统一题型配额

新增 `QuestionTypeQuotaPlan`，统一处理：

- 单选题 `choice`
- 多选题 `multi_choice`
- 填空题 `fill`
- 判断题 `true_false`
- 解答题 `subjective`

每个批次都根据剩余缺口生成精确题型任务；接收端会拒绝未知题型和超过配额的题目。最终只有“总题数达到目标且每一种题型配额都满足”才判定整卷成功。

同时修正了试卷提示词中的冲突：

- JSON 结构正式包含 `multi_choice`。
- 大题标题与题型建立唯一映射。
- 单选答案要求单个字母；多选答案要求至少两个字母组成的数组。
- 选择、判断、填空和解答题分别校验必要的选项与答案结构。
- 补题完成判断按剩余题型配额计算，不再只看总数量。

## F03：长资料与单题重生成

新增 `MaterialContextSelector`：

- 短资料保持原文不变。
- 长资料优先识别章节标题，并从开头、中部、结尾和命中关键词的章节抽取连贯片段。
- 无明确章节时，从整份资料均匀抽取多个窗口。
- 每段携带原文位置标记，避免把离散片段误认为连续改写。
- 普通出题、试卷、RPG 与小游戏均不再只截取资料开头。

单题重新生成的用户要求改为独立的最高优先级指令，并放在资料正文之前；即使原资料很长，“只改数值”“指定题型”等要求也不会再被尾部截断。
