# RC005 API 异常调用处理规则（产品草案）

本文件是产品与技术处理草案，不构成法律意见。

## 正常调用

用户主动执行生成或重生成，应用按任务记录发起预期请求。即使结果不符合主观预期，也不属于异常调用。用户可优先使用本地编辑；任何再次调用模型的按钮都应提示可能产生新的第三方额度消耗。

## 疑似应用缺陷

若一次用户操作因应用缺陷产生明显超出预期的重复请求：

1. 用户在“API 使用记录”复制脱敏 Task 凭证。
2. 同时核对服务商控制台时间和请求次数。
3. 通过“API 异常调用”Issue 模板或反馈渠道提交。
4. 开发者依据版本、Task、请求次数、重试次数和时间进行技术调查。
5. 经核实后进行缺陷修复并根据实际情况提供合理处理。

产品不写“任何损失一概由用户承担”，也不提前承诺无条件、固定金额或无限赔偿。

## 第三方服务商问题

如果本机任务记录正常，而服务商出现价格变化、计费错误、额度异常或接口故障，最终争议由服务商处理。AI题库可提供本机脱敏调用记录，但不能伪造账单或替服务商承诺退款。

## 生成结果不满意

优先使用不产生 API 调用的本地编辑：修改题干、选项、答案、解析、分值、顺序、删除或复制题目。确需 AI 重生成时，只重生成异常题，并在调用前明确提示可能产生新的服务商费用。

建议原因：太简单、太难、偏离资料、重复度高、表达不自然、答案有问题、解析过简或题型不合适。原因默认只用于本次 Prompt 优化并保存在本地。
