# AI题库 v3.0.0 RC006：试卷生成诊断与可靠性

## 问题背景

RC005 真机曾出现“目标 20 题，最终只保留 3 题”的情况。旧流程只反馈最终数量，无法区分是模型少返回、JSON 解析失败、结构校验失败，还是题目被去重与相关性规则过滤。

## RC006 处理方式

### 1. 真实批次规划

`PaperGenerationPlan` 将大任务拆为可恢复的小批次。20 题的默认计划为：

```text
3 + 3 + 3 + 3 + 3 + 3 + 2
```

复杂图表、长解析等任务仍可使用更小批次。界面只展示真实的批次与接收数量，不使用按时间增长的虚假百分比。

### 2. 分层诊断

批次解析器记录以下真实数据：

- 目标题数；
- 模型原始候选数量；
- JSON 成功解析数量；
- 结构合法数量；
- 过滤与去重后的接受数量；
- 当前累计数量；
- 失败批次与错误摘要。

以后再次发生“20 → 3”时，可以定位题目究竟丢失在哪一层，而不是依靠无限补题掩盖根因。

### 3. 部分成功可保存

`PaperGenerationResult` 支持：

- `success`：达到目标题数；
- `partial`：已有可用题目但未达到目标；
- `failed`：没有可保存结果；
- `cancelled`：用户主动取消。

已通过校验的题目会保留在草稿中。失败后用户可选择继续补齐或保存当前草稿，不会因为后续某个批次失败而丢失前面成功的题目。

### 4. 有限补题与 BYOK 保护

- 每批只允许初次请求和最多一次受控修复/重试；
- 用户取消后不再启动新批次；
- 达到安全请求边界后暂停，由用户确认是否继续；
- 图表题失败不拖垮普通题；
- 听力文本成功但音频失败时，题目仍保留；
- 所有实际模型调用继续经过 RC005 的 AI Cost Guard。

### 5. 本地容错优先

轻微 JSON 问题（代码围栏、前后说明、尾部噪声等）优先在本地清理和解析，不因可修复格式问题额外消耗一次模型请求。严重结构错误才进入有限修复流程。

## 自动化覆盖

- 20 题批次规划；
- 单批失败后保留已有题目；
- `partial` 状态；
- 继续补齐只计算缺失数量；
- 真实批次进度回调；
- 轻微 JSON 容错；
- 用户取消与安全停止边界。

## 仍需真机验证

- 使用 DeepSeek、Qwen、GLM、SiliconFlow、MiMo、Kimi 与自定义接口分别生成；
- 10/20/30 题真实资料测试；
- 断网、超时、切后台、锁屏及恢复；
- 图表与英语听力混合试卷；
- 不同模型输出上限下的批次表现。
